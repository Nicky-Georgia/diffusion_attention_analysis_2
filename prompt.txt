Да, для масштабирования с 16 до 75 samples я бы **не перезаписывал старый pilot-run**. Самый безопасный путь — сделать отдельный tagged run:

```text
outputs/sd15_75/...
annotations/sd15_75/...
prompts/sd15_75_prompts.jsonl
```

Тогда pilot `outputs/sd15/...` останется нетронутым, а вся новая серия будет лежать отдельно. Это минимизирует риск сломать файловую систему и старые результаты.

Я просмотрел структуру repo/configs и твой notebook. Важные моменты:

* `configs/01_capture/sd15_full.yaml` по умолчанию рассчитан на большой full-run: `max_prompts: 1000`, `num_seeds: 2`, `save_latents: true`, 3 activation modules и estimated storage 300 GB. Для 75 samples это надо обязательно переопределять. 
* Stage 2 localization уже использует `annotations/sd15` в config, но для нового tagged run нужно заменить на `annotations/sd15_75`. 
* Stage 3 обучает SAE на `mid_block.attentions.0`, `step=24`, что хорошо совпадает с нашими pilot-выводами. 
* Stage 4 в config всё ещё имеет `annotations_dir: annotations`, поэтому для новой структуры обязательно нужен override на `annotations/sd15_75`. 
* Override parser умеет читать списки через YAML-style значения, так что `capture.activation_modules=[mid_block.attentions.0]` и `metrics.steps=[0,24,49]` корректны. 

Ниже — безопасный набор ячеек для вставки в текущий notebook.

# Главная логика масштабирования

Для SD1.5 сейчас лучше так:

```text
Stage 1: 75 generated samples, save attention + only mid activation, no latents
Stage 2 masks: all 75 samples
Stage 2 localization: all available attention steps
Stage 3 SAE: all 75 mid activations, 5 epochs
Stage 4 dictionary: all 75 activations/masks, top-15 features per label
Stage 5 interventions: controlled subset, not all 75 samples
```

Так мы масштабируем эксперимент, но не ломаем старый pilot и не раздуваем storage. После успешного `sd15_75` можно будет перейти к transformer models уже с тем же принципом: отдельный `RUN_TAG`, отдельные output dirs, не перезаписывать pilot artifacts.
